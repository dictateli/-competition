# 合流 AI · AI 技术选型、集成与优化说明

## 1. 设计目标与约束

合流 AI 的 AI 能力不是做一个独立的聊天窗口，而是嵌入会议、文档、项目和自动化工作流的业务闭环。因此 AI 技术选型必须同时满足以下约束：

| 约束 | 说明 |
|---|---|
| 数据新鲜度 | 企业知识持续变化，AI 必须读取最新会议、文档和任务状态 |
| 可追溯 | 每个结论必须能关联到原文、页码、会议时间点或任务记录 |
| 权限一致 | AI 只能访问当前用户和工作空间有权访问的数据 |
| 低延迟 | 会议实时转写、文档问答和写作辅助必须让用户感到即时反馈 |
| 成本可控 | 模型调用需要分级、缓存、预算和用量统计 |
| 可替换 | 不锁定单一模型厂商，支持公有云、私有化和国产模型 |
| 可演示 | 比赛环境无模型密钥时也能完整演示核心闭环 |

基于这些约束，项目采用“业务服务层统一编排 + AI 能力适配层 + 可替换模型与知识底座”的总体方案。

## 2. AI 能力总体架构

```text
Vue 前端
  |  REST / SSE / WebSocket
  v
Java 业务服务层
  |  权限上下文、业务规则、人工确认、审计
  v
AI Orchestration
  |  Prompt 管理、模型路由、RAG、工具调用、内容安全
  v
AI 能力适配层
  |  LargeLanguageModel / RetrievalService / SpeechRecognitionService
  v
模型与知识底座
  |  LLM、Embedding、ASR、向量数据库、全文检索、对象存储
```

核心原则是：模型可以替换，业务编排不替换；知识可以更新，权限边界不放松；AI 可以生成建议，高风险动作必须由人确认。

## 3. 技术选型理由

### 3.1 大语言模型：LLM Gateway + 适配器模式

**选型方式**

- 业务代码只依赖统一的 `LargeLanguageModel` 接口，不直接依赖某一家厂商 SDK。
- 通过 `AiRequest` 传递 Prompt、工作空间和上下文 ID，通过 `AiAnswer` 返回内容、模型版本和引用。
- 生产环境可增加 LLM Gateway，实现模型路由、降级、配额、成本统计和内容安全。

**选择理由**

1. 避免厂商锁定：同一套业务逻辑可以切换云端模型、私有化模型或国产模型。
2. 便于分级路由：复杂总结使用高能力模型，简单分类使用低成本模型。
3. 便于故障降级：主模型超时或限流时自动切换到备用模型。
4. 便于合规：企业数据可以指定私有化模型或本地模型。
5. 便于演示：比赛版使用 `DemoLargeLanguageModel`，无密钥也能跑通闭环。

**当前实现**

- 接口：`com.heliu.ai.ai.api.LargeLanguageModel`
- 请求与响应：`AiRequest`、`AiAnswer`、`AiCitation`
- 演示实现：`com.heliu.ai.ai.demo.DemoLargeLanguageModel`

### 3.2 知识增强：优先 RAG，而非先做微调

**选择 RAG 的理由**

| 维度 | RAG | 微调 |
|---|---|---|
| 知识更新 | 文档更新后立即可检索 | 需要重新训练或重新发布 |
| 权限控制 | 检索前可按租户、项目、文档 ACL 过滤 | 权限难以细粒度控制 |
| 可追溯 | 天然可以返回原文引用 | 参数知识难以给出证据 |
| 成本 | 低，按调用计费 | 训练、存储和版本管理成本高 |
| 幻觉控制 | 可以强制引用和证据校验 | 仍可能记忆错误或过期信息 |

因此，项目把 RAG 作为企业知识问答的第一选择；微调只用于语气、格式、分类和特定领域表达优化，不用于承载频繁变化的业务知识。

**RAG 关键流程**

```text
用户问题
  -> 权限过滤
  -> Query Rewrite
  -> 向量召回 + 关键词召回
  -> Rerank
  -> 上下文压缩
  -> LLM 生成
  -> 引用校验
  -> 流式返回
```

**当前实现**

- 接口：`com.heliu.ai.ai.api.RetrievalService`
- 演示实现：`DemoRetrievalService`
- 统一知识检索：`com.heliu.ai.knowledge.service.KnowledgeService`
- 文档问答：`DocumentService.ask`
- 生产替换：Embedding 模型 + Milvus/Qdrant/pgvector + Elasticsearch/OpenSearch

### 3.3 向量检索与混合检索

**选型理由**

- 纯向量检索对语义相似问题效果好，但对专有名词、编号、合同条款和精确匹配不稳定。
- 纯关键词检索精确，但无法理解同义表达和跨语言问题。
- 混合检索把两者结合，再经过 Rerank，可以同时兼顾召回率和准确率。

**实现策略**

1. 文档解析后按标题、段落和表格进行分块。
2. 每个分块携带 `tenant_id`、`workspace_id`、`document_id`、`page`、`section`、`acl_tags`、`version`。
3. 检索前先做权限过滤，再做向量召回和关键词召回。
4. Rerank 后压缩上下文，减少无关内容和 Token 消耗。
5. 生成后再次校验引用范围，禁止越权引用。

### 3.4 语音识别：流式 ASR + 说话人分离

**选型理由**

- 会议场景需要边说边显示，不能等会议结束后再批量转写。
- 结论和行动项需要定位到原始发言时间点，因此必须保留时间戳。
- 多人会议需要区分说话人，才能正确生成负责人和决策链。

**集成方式**

- 前端通过 WebSocket 发送音频分片或文本分片。
- Java 会议服务调用 `SpeechRecognitionService`。
- 识别结果写入 `TranscriptSegmentEntity`，再广播给所有参会端。
- 会议结束后调用 LLM 生成摘要、决策和行动项。

**当前实现**

- WebSocket：`MeetingWebSocketHandler`
- 接口：`com.heliu.ai.ai.api.SpeechRecognitionService`
- 演示实现：`DemoSpeechRecognitionService`
- 生产替换：流式 ASR 服务、热词增强、说话人分离、时间戳对齐

### 3.5 工具调用与结构化输出

AI 不直接随意修改业务数据。工具调用遵循以下规则：

1. 工具白名单：只允许查询项目、创建任务、发通知、触发工作流等受控动作。
2. JSON Schema：任务、负责人、截止时间和风险等级必须结构化验证。
3. 人工确认：创建任务、发通知、修改文档等动作由用户确认后执行。
4. 幂等键：重复执行不会创建重复任务或重复通知。
5. 审计记录：记录工具名称、参数摘要、结果、耗时和操作者。

### 3.6 内容安全与权限

- 所有数据表包含 `workspace_id`，服务层强制拼接工作空间条件。
- 检索前做 ACL 过滤，生成后做引用校验。
- Prompt 注入防护：文档正文被视为数据，不执行其中隐藏的指令。
- 高风险输出进入人工确认队列。
- 生产环境支持 PII 脱敏、敏感词过滤、模型调用审计和私有化部署。

### 3.7 演示适配器与生产适配器

比赛版默认使用 Demo 适配器：

- `DemoLargeLanguageModel`：离线生成摘要、风险、周报和工作流说明。
- `DemoRetrievalService`：基于已上传文档做关键词评分和引用返回。
- `DemoSpeechRecognitionService`：把音频分片转换为演示转写文本。

生产环境新增实现类并通过 Spring Profile 切换即可，不需要修改业务控制器和服务层。

## 4. 集成方式

### 4.1 分层集成原则

```text
前端不持有模型密钥
  -> Java 业务服务统一鉴权和编排
  -> AI 适配层负责模型调用
  -> 数据层负责权限过滤和持久化
```

这样做的原因是：前端最容易被查看和篡改，模型密钥、Prompt 模板和权限判断必须放在服务端。

### 4.2 代码级集成接口

| 能力 | 接口 | 当前演示实现 | 生产替换方向 |
|---|---|---|---|
| 大模型生成 | `LargeLanguageModel` | `DemoLargeLanguageModel` | LLM Gateway、私有模型、国产模型 |
| RAG 检索 | `RetrievalService` | `DemoRetrievalService` | 向量库、混合检索、Rerank |
| 语音识别 | `SpeechRecognitionService` | `DemoSpeechRecognitionService` | 流式 ASR、热词、说话人分离 |

业务服务通过构造器注入接口，Spring 在启动时选择实现。这样既保证比赛版离线可运行，也保证生产版可以平滑替换。

### 4.3 协议集成

| 场景 | 协议 | 原因 |
|---|---|---|
| 普通业务查询 | REST | 简单、稳定、易调试 |
| 大模型写作和文档问答 | SSE | 逐字返回，降低等待感 |
| 会议实时转写 | WebSocket | 双向、低延迟、适合音频分片 |
| 文档解析和向量化 | MQ 异步任务 | 避免阻塞上传请求，支持重试 |
| 外部通知 | Webhook / 企业微信 / 钉钉 / 飞书 | 连接企业现有协作工具 |

### 4.4 关键业务链路

**会议到行动**

```text
音频分片
  -> WebSocket
  -> ASR
  -> 转写分段
  -> 会议结束
  -> LLM 摘要与决策提取
  -> 行动项结构化
  -> 用户确认
  -> 写入项目任务
  -> 生成通知
```

**文档到知识**

```text
上传文档
  -> 解析文本/表格/OCR
  -> 分段与权限标签
  -> Embedding
  -> 写入向量库和全文索引
  -> 生成摘要与风险
  -> RAG 问答
```

**知识问答**

```text
问题
  -> 身份与权限过滤
  -> Query Rewrite
  -> 混合召回
  -> Rerank
  -> 上下文压缩
  -> LLM 生成
  -> 引用校验
  -> SSE 返回
```

**自然语言自动化**

```text
自然语言目标
  -> LLM 解析触发条件
  -> 生成 AI 分析节点
  -> 生成业务动作节点
  -> 用户确认
  -> 工作流运行
  -> 结果回流知识库
```

### 4.5 配置与环境切换

- 使用 `application.yml`、`application-prod.yml` 和 Spring Profile 管理 Demo 与生产配置。
- 模型密钥、数据库地址、Redis、MinIO 和消息队列通过环境变量注入。
- `heliu.seed-demo-data=false` 可以关闭演示数据，避免生产环境写入示例内容。
- `X-Workspace-Id` 用于多租户上下文传递，默认使用 `ws-demo`。

### 4.6 当前代码映射

| 模块 | 关键类 | 职责 |
|---|---|---|
| AI 接口 | `com.heliu.ai.ai.api.*` | 定义模型、RAG、ASR 适配接口 |
| AI 演示实现 | `com.heliu.ai.ai.demo.*` | 离线可运行的 Demo 能力 |
| 会议 | `MeetingService`、`MeetingWebSocketHandler` | 转写、纪要、行动项转任务 |
| 文档 | `DocumentService` | 上传、分析、对比、RAG 问答 |
| 知识中枢 | `KnowledgeService` | 跨源检索、统计、问答 |
| 项目 | `ProjectService` | 任务、依赖、风险、负载 |
| 工作流 | `WorkflowService` | 自然语言创建、运行、重试 |
| 通知 | `NotificationService` | AI 结果触发业务通知 |
| AI 写作 | `WritingController` | SSE 流式写作 |

## 5. 优化策略

### 5.1 质量优化

1. **混合检索**：向量召回加关键词召回，提升专有名词和条款检索命中率。
2. **Query Rewrite**：把口语问题改写为更适合检索的查询。
3. **Rerank**：对候选片段重新排序，优先保留高相关内容。
4. **上下文压缩**：去除重复和低相关段落，降低噪声。
5. **引用强制**：无法找到证据时回答“不确定”，不编造来源。
6. **结构化校验**：任务、负责人、时间、风险使用 JSON Schema 校验。
7. **人工反馈闭环**：记录采纳、修改、拒绝结果，用于优化 Prompt 和排序。

### 5.2 延迟优化

1. SSE 流式输出，首字响应时间明显降低。
2. 会议使用 WebSocket，转写结果实时广播。
3. 文档解析、OCR、Embedding 放入异步队列，不阻塞上传接口。
4. 检索和权限过滤并行执行，减少串行等待。
5. 热点知识和高频问答结果缓存。
6. 简单任务路由到小模型，复杂任务路由到大模型。

### 5.3 成本优化

1. 模型分级：摘要、分类、抽取、生成使用不同能力等级模型。
2. Token 预算：按租户、工作空间和场景设置调用上限。
3. 上下文压缩：只携带必要片段，而不是整篇文档。
4. Embedding 批量化和增量更新，避免全量重算。
5. 结果缓存：相同问题和相同版本知识直接复用。
6. 用量统计：记录模型、Prompt 版本、输入输出 Token、耗时和成本。

### 5.4 可靠性优化

1. 超时、重试、指数退避和熔断。
2. 主模型失败时自动切换备用模型。
3. 文档解析和向量化使用幂等键、重试次数和死信队列。
4. 工作流运行记录状态、输出、错误和耗时，支持失败重试。
5. AI 输出失败时，业务系统仍可查看原始会议、文档和任务。

### 5.5 安全与合规优化

1. 租户隔离：所有数据表包含 `workspace_id` 或 `tenant_id`。
2. 权限前移：检索前过滤，生成后校验引用范围。
3. 提示注入防护：文档内容不作为系统指令执行。
4. 敏感信息处理：PII 脱敏、密钥隔离、私有化部署选项。
5. 审计：登录、查看、下载、分享、AI 调用和工作流执行全量留痕。

### 5.6 可观测性与评测

每次 AI 调用建议记录：

| 字段 | 说明 |
|---|---|
| `trace_id` | 串联前端请求、业务服务、模型调用和数据库操作 |
| `model` | 模型名称和版本 |
| `prompt_version` | Prompt 模板版本 |
| `latency_ms` | 端到端耗时和模型耗时 |
| `input_tokens` / `output_tokens` | 成本统计 |
| `citation_hit` | 引用是否命中有效来源 |
| `user_action` | 采纳、修改、拒绝 |

核心评测指标：

- 会议纪要和行动项采纳率。
- 文档问答引用命中率。
- 高风险任务提前发现率。
- AI 建议行动项完成率。
- 首字响应时间和 P95 延迟。
- 单次工作流模型成本。
- 幻觉率和人工纠正率。

## 6. 当前版本与生产版本对比

| 能力 | 当前比赛版 | 生产版建议 |
|---|---|---|
| LLM | Demo 适配器 | LLM Gateway + 多模型路由 |
| RAG | Demo 关键词检索 | 向量库 + 混合检索 + Rerank |
| ASR | Demo 转写 | 流式 ASR + 热词 + 说话人分离 |
| 数据库 | H2 文件数据库 | MySQL 8 + Flyway |
| 缓存 | 无 | Redis |
| 文件存储 | 本地或演示元数据 | MinIO / S3 |
| 异步任务 | 同步演示 | RabbitMQ / Kafka |
| 安全 | PermitAll 演示配置 | OAuth2 / OIDC + JWT + RBAC/ABAC |
| 审计 | 基础日志 | 全量操作与模型调用审计 |

## 7. 结论

合流 AI 的 AI 技术方案以“可替换、可追溯、可控制、可优化”为核心：

- **选型理由**：RAG 优先保证知识新鲜和引用可追溯，适配器模式避免厂商锁定，流式 ASR 和 SSE 保证实时体验。
- **集成方式**：前端不接触密钥，Java 服务统一编排，AI 能力通过接口注入，REST、SSE、WebSocket 和 MQ 按场景组合使用。
- **优化策略**：从质量、延迟、成本、可靠性、安全和可观测性六个维度持续优化，并用评测指标驱动迭代。

这套方案既能在比赛环境无密钥、无外网依赖的情况下完整演示，也能在生产环境平滑替换为真实模型、向量数据库和企业级安全体系。
