合流 AI · 使用文档（逐步骤版）
================================
最后更新：2026-10-17

本文件说明从零开始把「合流 AI」跑起来的每一个步骤，包含排错方法。
全部操作都在 Windows 上完成；后端不需要联网，前端构建需要联网装一次依赖。

二、登录账号
--------------------------------
后端启动后会自动创建三个演示账号：

    账号      密码        角色
    ----    --------    --------
    linran  heliu123    产品负责人
    zhao    heliu123    项目经理
    demo    demo1234    成员

登录是真实校验的：密码错返回 401，登录成功发 token，之后所有接口
都要带这个 token，没带或过期一律 403 拒绝。
token 怎么拿、程序怎么调用，见第四章。


三、启动后端（每一步都写清楚）
--------------------------------
前置条件：无。后端自带 Java 17，不需要你电脑装过 Java，也不需要联网。

第 1 步：打开 backend\dist 目录
    资源管理器进入 D:\competition\backend\dist\

第 2 步：双击 run.cmd
    会弹出一个黑色控制台窗口。第一次启动约 20~60 秒，请耐心等。

第 3 步：确认启动成功
    打开浏览器访问：
        http://localhost:8080/swagger-ui.html
    能看到接口文档页面，说明后端完全正常。

第 4 步：启动前端（两种方式，任选其一）

    方式 A · 开发模式（热更新，改代码用）
        在 frontend\ 目录打开 PowerShell：
            cd D:\competition\frontend
            npm run dev
        然后打开 http://localhost:5173/
        开发服务器会自动把 /api 请求转发到 8080，登录后直接调试。

    方式 B · 生产构建（给别人演示用）
            cd D:\competition\frontend
            npm run build
        产物在 frontend\dist\ 里，把它发布到任意静态服务器即可。
        本地快速预览：
            npm run preview
        然后打开 http://localhost:4173/

第 5 步：让前端连后端
    前端默认走同源后端；开发模式下 Vite 自动转发，无需配置。
    构建后部署到别处时，通过地址栏传参：
        http://你的地址/login.html?api=http://localhost:8080/api/v1
    顶栏显示「后端已连接 · 实时数据」就连上了。
    后端没开时自动回退到演示数据，不会白屏。

第 6 步：关闭
    后端：关掉黑色控制台窗口。
    前端 dev：在对应 PowerShell 里按 Ctrl+C。


四、如何调用后端 API（程序、Postman、第三方系统接入）
--------------------------------
后端地址 http://localhost:8080，业务接口统一前缀 /api/v1。
除「登录 / 注册」外全部接口都要 token，接入三步：登录拿 token →
之后请求都带上 → 不用了就登出。

第 1 步：登录拿 token（PowerShell 示例）

    $resp = Invoke-RestMethod -Uri http://localhost:8080/api/v1/auth/login `
        -Method Post -ContentType 'application/json' `
        -Body '{"username":"linran","password":"heliu123"}'
    $token = $resp.data.token
    $token

    成功返回（节选）：
    {"success":true,"data":{"token":"tok-971b0f3e1c334f51...","user":{...},"permissions":[...]}}
    失败返回：
    {"success":false,"data":null,"message":"账号或密码错误"}

    curl 用户的写法（PowerShell 里 curl 是别名，请写 curl.exe）：
    curl.exe -X POST http://localhost:8080/api/v1/auth/login -H "Content-Type: application/json" -d "{\"username\":\"linran\",\"password\":\"heliu123\"}"

第 2 步：之后每个请求都带上 Authorization 头

    Invoke-RestMethod -Uri http://localhost:8080/api/v1/me `
        -Headers @{ Authorization = "Bearer $token" }

第 3 步：登出（token 立即失效）

    Invoke-RestMethod -Uri http://localhost:8080/api/v1/auth/logout `
        -Method Post -Headers @{ Authorization = "Bearer $token" }

统一响应格式
    成功 {"success":true,"traceId":"...","data":<结果>,"message":"ok","timestamp":"..."}
    失败 {"success":false,"traceId":"...","data":null,"message":"<原因>","timestamp":"..."}
    先看 success 字段：false 时 message 就是给人看的失败原因。

token 注意事项
    · 有效期 8 小时，过期后需重新登录（会返回 403）
    · 存在后端内存里：后端重启后所有 token 失效，要重新登录
    · 登出即刻失效
    · token 本身不含用户信息，泄漏了别人就能用，请妥善保管

常见状态码
    200 成功      401 账号或密码错（登录接口）
    403 没带 token / token 过期 / 权限不足
    409 注册时账号被占用
    500 服务器异常（看后端控制台日志）

不用 token 也能调的接口
    POST /api/v1/auth/login       登录
    POST /api/v1/auth/register    注册
    GET  /actuator/health         健康检查
    GET  /swagger-ui.html         接口文档
    GET  /h2-console              数据库控制台
    /ws/**                        WebSocket（会议转写等）

推荐先看 Swagger
    浏览器打开 http://localhost:8080/swagger-ui.html，全部接口
    都能在线查看并直接调试（右上角 Authorize 填 Bearer <token>），
    不用手写命令。找不到接口时先来这里搜。

常用接口速查（都需 token）
    GET  /api/v1/me                      当前登录用户
    GET  /api/v1/dashboard               AI 工作台
    GET  /api/v1/workspaces              工作空间列表
    GET  /api/v1/projects                项目列表
    GET  /api/v1/meetings                会议列表
    POST /api/v1/meetings                创建会议
    POST /api/v1/documents               上传文档（multipart，≤ 50 MB）
    GET  /api/v1/documents               文档列表
    POST /api/v1/knowledge/ask           知识库 RAG 问答
    GET  /api/v1/knowledge/search        知识检索
    POST /api/v1/copilot/chat            Copilot 对话
    POST /api/v1/ai/writing              AI 写作
    POST /api/v1/workflows/from-prompt   自然语言生成工作流
    GET  /api/v1/notifications           通知列表

前端页面怎么连后端
    开发模式 npm run dev：Vite 自动转发 /api 到 8080，零配置。
    构建后部署到别处：
        http://你的地址/login.html?api=http://后端地址:8080/api/v1
    或在页面里设置 window.HELITU_API_BASE = 'http://localhost:8080/api/v1'
    （登录成功后前端会把 token 存进浏览器 sessionStorage，
     之后的请求自动加 Authorization: Bearer 头，无需手工处理）


五、文档上传与 PDF 解析
--------------------------------
「文档分析」页面上传的文档现在会被 Apache Tika 真实解析：

    支持：.pdf .doc .docx .xls .xlsx .ppt .pptx .txt .md .csv .json
    上传上限：50 MB

上传后自动提取全文 → 生成摘要与风险提示 → 写入知识库 → 可 RAG 问答。
纯文本类（.txt/.md/.csv/.json）直接读原文；PDF/Office 由 Tika 抽取文本。

注意：扫描件、纯图片 PDF 没有文字层，会提示「未能提取到文本内容」。


六、启动失败怎么排查（按顺序试）
--------------------------------
【问题 1】双击 run.cmd 一闪就关了
    按 Win+R 输入 cmd 回车，执行：
        D:
        cd \competition\backend\dist
        run.cmd
    窗口不会关，能看到完整报错。

【问题 2】报 "Unable to determine Dialect" 或数据库连不上
    1) 删掉 D:\competition\backend\dist\data\heliu.lock.db
    2) 确认 data 目录可写（右键→属性，取消「只读」）
    3) 重新双击 run.cmd

【问题 3】端口 8080 被占用
    管理员 PowerShell 执行：
        Get-Process java -ErrorAction SilentlyContinue | Stop-Process -Force
    再重新启动。

【问题 4】登录提示「账号或密码错误」但账号没错
    确认后端是新版（dist\app.jar 约 104 MB）。旧版不校验密码直接放行。
    还不行就重置数据库：
        Remove-Item -Recurse -Force "D:\competition\backend\dist\data"
    重启后自动重建演示账号。

【问题 5】前端 npm run dev 报错
    先确认 Node.js 版本 ≥ 18：
        node --version
    依赖损坏时重装：
        cd D:\competition\frontend
        Remove-Item -Recurse -Force node_modules
        npm install

【问题 6】调接口返回 403 但明明登录成功了
    多数情况是 token 过期或后端重启过（token 存在内存里）。
    重新登录拿新 token 即可。

八、切换到 DeepSeek 真实模型（可选）
--------------------------------
默认用 Demo 模型（不需要密钥）。想用 DeepSeek：

第 1 步：管理员身份打开 PowerShell
第 2 步：执行
    $env:HELIU_AI_PROVIDER='deepseek'
    $env:DEEPSEEK_API_KEY='你的 API Key'
第 3 步：同一窗口启动后端
    D:
    cd \competition\backend\dist
    .\run.cmd
没有 Key 时自动回退到 Demo 模型。


九、想改代码重新构建（可选）
--------------------------------
【后端】需要 Maven 并联网：
    cd D:\competition\backend
    .\mvnw.cmd clean package -DskipTests
    .\scripts\sync-dist.ps1
mvnw.cmd 首次运行会下载 Maven；构建出的 jar 自动同步到 dist\app.jar。

【前端】
    cd D:\competition\frontend
    npm run build
产物在 frontend\dist\。改组件源码后重新 build 即可。


十、重置演示数据（含账号）
--------------------------------
删掉数据库目录后重启后端，自动重建演示账号和演示数据：

    Remove-Item -Recurse -Force "D:\competition\backend\dist\data"

执行后所有登录中的 token 也会全部失效，需要重新登录。
